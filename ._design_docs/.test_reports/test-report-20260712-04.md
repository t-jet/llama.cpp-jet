## Failure and blocker section

No product FAIL in this run. The prior TP-39-15 FAIL and the Stage 10 cold-bytes
gauge FAIL are both reclassified PASS here on the fresh build.

Driver-script regression (test harness, not product): the F39-QA3-01 fix added a
strict per-line label-name validation loop in
`stage39-two-layer-pressure.ps1:185-194`. That loop iterates
`$decisions + $transactions`; when a scenario emits zero Stage 39 rows (legacy,
hot-zero), PowerShell's `Where-Object` returns `$null`, so
`@($null + $null) = @($null)` and the loop throws a "Malformed Stage 39 metric
row" with an empty `$line` before the legacy/hot-zero
short-circuit at line 195. Effect: the live driver no longer completes for
legacy or hot-zero scenarios, so no `summary.json` is written for those two
rows. The product behaviour is correct (verified directly on the
`metrics-after.txt` scrapes, both showing zero Stage 39 rows), so TP-39-05 and
TP-39-11 PASS on product evidence. The script guard needs a small Developer fix
(filter empty/null before the loop or short-circuit earlier).

Calibration BLOCKED (TP-39-02/03/04): with the only available generative
fixture (Qwen3-0.6B, ~8-11 MiB resident pairs), the hot-budget rejection fires
upstream of the two-layer decision for small cold budgets, and at larger budgets
every demotion succeeds as `retained_cold/cold_room_made`. No budget/fixture
combination on this host reaches `evicted/both_filled`, `evicted/oversized_both`,
or an equal-rank tie-break victim series. The Architect re-review and Developer
part-33 both left these open as harness-precondition; QA confirms the same
outcome with fresh oversized-both evidence (`live-oversized-both`).

`<coverage line-rate="1" ... lines-valid="0" lines-covered="0" .../>` with empty

`test-cache-controller.exe`, so OpenCppCoverage's module filter instruments none
of them against the focused test process. The test exercises the cache logic via
its own compiled-in copies/shims.

Console log tail (`coverage/hybrid-stderr.log`) confirms the test ran fully under
the tracer (Stage 39 decision and transaction log lines present) and OpenCppCoverage
exited 0, but recorded zero product lines.

Classification: coverage is BLOCKED-infrastructure. A real smoke `.cov` exists
(satisfying the "produce at least one `.cov` before reporting a percentage"
rule), but the changed-line percentage cannot be computed because the artifact
captures zero product lines. The 80% binding threshold from the Stage 10 closure
contracts cannot be evaluated on this evidence. This is a tooling/module-mapping
gap, not a product defect.

A path forward for a future coverage attempt (out of scope here): run the server
probe phase of `run_coverage.ps1` against `llama-server.exe` (which links the
hybrid `.cpp` sources as real modules) so OpenCppCoverage can instrument the
