## Findings

### F-18-EXEC-01: F-18-DR-01 corner case crashes with STATUS_STACK_BUFFER_OVERRUN

- Severity: blocking (drives FAIL on IT1)
- Evidence: IT1/server.err.log full body. Server starts and reaches `0.00.786.046 I common_init_from_params: warming up the model with an empty run - please wait ...` at 786ms. At 965ms the process exits with code -1073740791 (0xC0000409 = STATUS_STACK_BUFFER_OVERRUN). The bounded error `--cache-cold-path requires --cache-mode hybrid` from server-context.cpp:1419-1420 does NOT print. The check at lines 1413-1414 (cited by F-18-IMPL-02) is `cache_cold_max_mib != 0 && path not empty && != HYBRID`; for `--cache-cold-max-mib 0` the condition is FALSE, so that check does not fire. The earlier check at lines 1409-1410 (`max_mib != -1 && != HYBRID`) should fire (max_mib=0 satisfies `!= -1`; legacy satisfies `!= HYBRID`), but the crash occurs during warmup before either check can execute.
- Control: IT2 with `--cache-mode hybrid` started cleanly; IT2 is the proof that the hybrid path is unaffected. The crash is specific to the F-18-DR-01 corner case (`legacy + cold-path + 0 budget`).
- Root-cause hypothesis: a buffer overrun in the warmup path of load_model() that the cache validation block at server-context.cpp:1409-1420 would have caught, but the crash precedes the validation. The Stage 18 design review (F-18-DR-01) predicted the duplicate at 1554-1557 was unreachable; the implementation review (F-18-IMPL-02) asserted the corner case is rejected at 1413-1414. Both assumptions are wrong for the `max_mib=0` case: the check at 1413-1414 does not fire, and the crash happens before any check at 1409-1420 fires. The empirical closure of F-18-DR-01 from the iter 2 review did not cover the `max_mib=0` sub-case.
- Action: Developer to (1) reproduce the STATUS_STACK_BUFFER_OVERRUN on the warmup path of load_model() when `cache_mode_val != HYBRID` and `cache_cold_path` is set (with or without `cache_cold_max_mib`); (2) either move the cache validation block at server-context.cpp:1409-1420 to BEFORE the model warmup, or fix the buffer overrun in the warmup path itself. The validation should fire before any model load step. Confirm safe path: hybrid + cold-path; legacy + no cold-path; legacy + cold-path + max_mib=0 (must reject with bounded error, not crash).

### F-18-EXEC-02: F-17-EXEC-01 fix regressed; raw prompt evidence crashes with STATUS_STACK_BUFFER_OVERRUN

- Severity: blocking (drives FAIL on IT3; same crash family as F-18-EXEC-01)
- Evidence: IT3/server.err.log full body. Server starts and reaches `0.00.774.586 I common_init_from_params: warming up the model with an empty run` at 774ms. At 961ms the process exits with code -1073740791 (0xC0000409 = STATUS_STACK_BUFFER_OVERRUN). The bounded error `raw prompt evidence requires --log-prompts-dir` from server-context.cpp:1407 does NOT print. The validation block at server-context.cpp:1401-1408 is reached only after model warmup, so the crash precedes the validation.
- Control: per test-report-20260617-01.md F-17-EXEC-01, the Stage 17 fix moved (or attempted to move) the validation block to the top of load_model(). The fix is not in the post-F-18-IMPL-01 binary; the crash returns under the same flags that previously crashed.
- Root-cause hypothesis: identical to F-18-EXEC-01. The cache validation block at server-context.cpp:1401-1420 runs after the model warmup. Any configuration that violates the validation rules triggers a buffer overrun in the warmup path before the validation can throw a bounded error. The Stage 17 fix is incomplete: the validation block is in the right function but at the wrong position (after warmup instead of before).
- Action: Developer to (1) move the entire cache validation block at server-context.cpp:1401-1420 to BEFORE the model load / warmup step in load_model(); (2) verify both F-18-EXEC-01 (legacy + cold-path + max_mib=0) and F-18-EXEC-02 (raw + no log-prompts-dir) now exit with bounded errors; (3) verify all other cache validation rules (max_mib < -1, max_mib positive + no path, etc.) still throw bounded errors from the same block. Confirm safe path: raw + log-prompts-dir set; redacted mode (any).
