## Overall verdict

FAIL. The Stage 16 fix is BROKEN on the MTP fixture. The new
`MESSAGE_END` boundary at `[0, n_prompt_tokens]` is emitted by
`cache_metadata_from_chat_messages` (verified: log line `cache
metadata: source=openai-chat method=rendered-text-boundary-inference
degraded=rendered text boundary inference tokens=61 boundaries=9`,
8 per-message + 1 prompt-span = 9 boundaries), but the strict
validator at `server-cache-hybrid.cpp:2984` still rejects the
checkpoint with `missing checkpoint boundary metadata`.

Root cause: the descriptor-build loop at
`server-cache-hybrid.cpp:3066-3078` picks the FIRST boundary whose
`token_end == descriptor.token_span_end`. The MTP fixture's
speculative-decoding internal checkpoint is created at position 10
(`pos_min = 10, pos_max = 10, n_tokens = 11`) after the first
speculative step, not at the end of prefill. The new prompt-span
boundary's `token_end = n_prompt_tokens = 61` does not match the
checkpoint's `n_tokens = 11`. The fallback path
(`server-cache-hybrid.cpp:3081`) sets
`checkpoint_boundary_required = true` but never populates
`boundary_id`/`checkpoint_boundary_kind`/`boundary_checksum`, so
the strict validator returns `missing checkpoint boundary metadata`.

The fix design assumed the first end-of-prefill checkpoint has
`n_tokens == n_prompt_tokens`, which is true on the V2
separate-draft fixture but NOT on the MTP fixture (speculative
decoding creates internal checkpoints at every `min spacing = 256`
step boundary, with the first one at position 10 regardless of
prompt length).

### F-16-TR-02: Stage 16 fix is broken on the MTP fixture

- Severity: blocking (drives the FAIL verdict on PC1, PC2, PC3,
  PC4, PC5, PC6)
- Evidence: server.err.log after 30 chat-completion requests:
  `cache metadata: source=openai-chat method=rendered-text-boundary-inference
  degraded=rendered text boundary inference tokens=61 boundaries=9`
  (9 boundaries = 8 per-message + 1 prompt-span; the new
  prompt-span boundary IS emitted). Followed by
  `save_slot: hybrid cache: checkpoint admission skipped
  (missing checkpoint boundary metadata)` and
  `cache_checkpoint_admissions_total=0`.
  `cache_checkpoint_admission_failures_total=1` after the first
  request. Same pattern on /completion (PC6):
  `cache_checkpoint_admission_failures_total=1` after first save,
  hits=0, misses=30, admissions=0.
- Root cause: the MTP fixture's speculative-decoding internal
  context checkpoint is created at position 10 with
  `n_tokens=11` (a speculative step boundary, not end-of-prefill).
  The fix adds a prompt-span boundary at `token_end=n_prompt_tokens`
  (= 61 in PC1-PC3, 27 in /completion on V2 prompt). The
  descriptor-build loop at `server-cache-hybrid.cpp:3066-3078`
  matches the first boundary with `token_end == checkpoint
  n_tokens`; no such boundary exists. The fallback at line 3081
  sets `checkpoint_boundary_required=true` with empty
  `boundary_id`/`checkpoint_boundary_kind`, and the strict
  validator at line 2984 returns `missing checkpoint boundary
  metadata`.
- Action: Developer handoff to expand fix scope. Three closure
  options (in priority order):
  1. Add a separate prompt-span boundary at `[0, checkpoint
     n_tokens]` for every checkpoint created during prefill, not
     just at end-of-prefill. This requires per-checkpoint
     metadata emission and a multi-boundary validator pass.
  2. Relax the descriptor-build loop to pick any prompt-span
     boundary whose `token_end >= checkpoint n_tokens` and re-
     checksum the boundary span over the actual checkpoint
     token range. This is the Option B scope that the Stage 16
     design excluded.
  3. Reclassify the MTP fixture as `NOT-IN-SCOPE` for
     `/v1/chat/completions` exact-blob restore, per Stage 15
     Manager decision 1, and document the
     `B02/B05/B06 NOT-IN-SCOPE` reclassification as still
     active.
